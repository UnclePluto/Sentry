# 双 Sheet 导入、样本维度统计与大盘调整

Status: ready-for-agent

日期：2026-09-21

本规格依据用户的新需求及继续使用 PostgreSQL 的决定编写。用户选择方案 A、审阅更新后的存储设计后，于 2026-09-21 要求继续，进入实施计划阶段；尚未实施、迁移或上线。位置遵循 `docs/agents/issue-tracker.md` 的本地规格约定。本轮不提交代码，不改动用户已有的部署文档修改。

## 1. 目标、范围与设计默认值

管理员上传包含 Sheet1 样本结果、Sheet2 检测病原体范围的 Excel。N 表示样本对本次检测范围全部阴性；具体病原体记录表示检出。总览、地图与统计均按样本计数，选择多个病原体时按 OR 判断阳性，同一样本最多计一次。

本次包含数据库结构、导入校验、可重建汇总、多选筛选接口、上传预览文案和大盘布局。继续使用 PostgreSQL、既有后台任务与整批作废，不引入 Redis、新数据库、机构管理、逐条检测明细页面或原文件下载。

用户后续已确认：不同 Excel 的 Sheet2 检测范围可以不同；多选采用方案 A，即至少检测过一种所选病原体的样本进入分母，检出任意一种所选病原体的样本进入分子。检测了部分所选病原体的样本也参与统计。未命中表示“实际检测的所选病原体中未检出”，不能推断其未检测项目为阴性。这项决定替代初稿的完整覆盖分母建议。

下列内容是本规格采用的设计默认值，不表述为用户已经逐项确认的事实；书面审阅覆盖这些规则：

1. sam 在同一 Excel 内唯一标识样本；一个样本的多个阳性行重复使用同一个 sam。不同上传仍独立累计，不按 sam 跨上传合并。batch 是样本属性，同一 sam 的 batch 不得冲突。
2. Sheet2 对本文件所有样本声明同一个、完整的检测范围。单文件多个检测面板、不同样本只测其中部分病原体，不在此格式的表达能力内，应拆成不同文件。
3. 新格式是完整检测报告；空结果、待复核、部分失败不能被当作阴性。CT 是附加属性，具体代码行已经声明检出；不再仅按 CT 文本推断阳性状态。
4. “监测区域”按当前地图展示层级的有样本区域去重计数，单位“个”；“检出病原体总数”表示不同病原体的种数，单位“种”。

成功标准是同一样本的多病毒记录不会扩大样本数、全阴性样本不会丢失、多选不会重复计算阳性，未测病毒不会被当作阴性，各模块统计能与明细重算结果核对。

## 2. 与旧行为的差异

现有 `server/parser.mjs` 只读取 Sheet1，直接剔除 N 或 CT 横线行；`samples` 用上传批次、batch、sam 唯一标识；`results` 保存显式阴阳性；`import_metrics` 只支持全部和单病原体汇总。`server/store.mjs` 的大盘参数和前端状态都只有单个 pathogen。

本规格批准后，新格式的导入和统计规则替代旧规格中“只读取 Sheet1”“N 剔除”“横线整行剔除”“batch + sam 标识统计单位”的规则。旧历史数据保留原格式版本与含义，不静默重新解释。账号权限、文件临时生命周期、批次独立累计、日期地区规则、任务重试及整批作废沿用现有要求。

## 3. 表结构与关系

### 3.1 核心事实表

| 表 | 关键字段 | 约束与含义 |
| --- | --- | --- |
| `imports` | 既有字段；新增 `format_version smallint` | 历史为 1，新双 Sheet 格式为 2；增加 `(id, format_version)` 唯一约束供复合外键使用 |
| `pathogens` | `code text PK`、`name text` | 复用字典；新格式禁止把 N 写入字典或检测范围；旧字典中遗留的 N 不自动删除 |
| `import_pathogens` | `import_id text`、`pathogen_code text`、`raw_name text`、`source_row integer` | 主键 `(import_id, pathogen_code)`；分别关联上传与病原体；每次上传独立保存 Sheet2 快照 |
| `samples` | 既有 `id bigint`、`import_id`、`batch`、`sample_code`；新增 `format_version`、`result_kind`、`source_row` | 格式 2 的部分唯一索引 `(import_id, sample_code)`；增加 `(import_id, id)` 唯一约束；复合外键 `(import_id, format_version)` 对应 imports |
| `sample_detections` | `import_id text`、`sample_id bigint`、`pathogen_code text`、`ct double precision NULL`、`raw_value text`、`raw_name text`、`source_row integer` | 主键 `(sample_id, pathogen_code)`；复合外键 `(import_id, sample_id)` 对应 samples，`(import_id, pathogen_code)` 对应 import_pathogens |

`samples.result_kind` 在格式 2 中必须是 `all_negative` 或 `has_positive`，来源行号为该样本第一条结果行。格式 1 的这些新增属性允许为空，不伪造旧数据来源。旧有 `(import_id, batch, sample_code)` 唯一约束可以保留，新增部分唯一索引只对格式 2 生效，避免已有跨 batch 同名 sam 导致结构迁移失败。

result_kind 只描述样本在本次上传全部检测范围中的结果，不保存“当前筛选下的阴性/阳性”。例如只检出 ADV 的样本在选择 IAV 时可能计为未检出，但不能把样本持久化状态改为 all_negative。按筛选得到的分子、分母和阳性率均为查询结果。

`import_pathogens` 与 `sample_detections` 仅由格式 2 发布流程写入。额外保存 detection 的 import_id 是为了在数据库层强制“此样本与此病原体属于同一上传”，不是另一份可独立修改的归属信息。

不为每个样本展开阴性病原体行，也不把 N 当作虚拟病原体。只有检测范围已知、完整报告校验通过时，范围内未出现在阳性明细中的病原体才能解释为阴性；范围外为未检测。

跨表业务约束在发布事务和重建校验中检查：全阴性样本的阳性明细数必须为 0；阳性样本至少有 1 条明细；每份上传至少有 1 个样本、1 个检测病原体。检查不通过必须回滚，不可发布只写完样本的中间状态。

旧 `results` 保留用于历史审计和旧口径核对；新格式不同时写入旧 results 与新 detections，避免两套事实源。后续删除旧表不属于本次范围。

### 3.2 可重建统计表

继续使用 `import_metrics(import_id, pathogen_code, tested, positive)`，主键不变，保留当前空代码表示“全部”的内部约定：

- 全部行：tested 为该上传样本总数；positive 为具有至少一种检出的样本数。
- 每个 Sheet2 病原体一行：tested 为该上传样本总数；positive 为该病原体的阳性样本数。
- 即使某病原体阳性数为 0，也要生成对应汇总行，以保留真实检测分母。
- 阴性样本数由 tested − positive 计算；阳性率不持久化，避免汇总时错误地平均比例。
- 格式 1 的既有指标不改写成格式 2，读取时通过 imports.format_version 区分。

新增 `import_detection_groups`：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `import_id` | text | 关联上传批次 |
| `group_no` | integer | 本次重建内的组合序号；与 import_id 组成主键 |
| `positive_codes` | text[] | 一个实际出现的阳性集合，排序、无重复、无 NULL；全阴性为非 NULL 的空数组 |
| `sample_count` | bigint | 此组合的样本数，必须大于 0 |

组合序号只用于标识汇总行，不暴露为业务标识。按规范化数组分组生成实际出现的组合，不枚举全部可能组合；使用序号主键避免将长度不固定的数组直接作为 B-tree 唯一键。写入时校验同一上传不重复出现等价组合；整批重建替换，不逐样本修改计数。

必须满足：组合 sample_count 之和等于总样本数；非空组合之和等于总阳性样本数；包含某代码的组合之和等于该病原体汇总的阳性数。组合表是派生数据，可从样本和阳性明细完全重建。

### 3.3 索引和容量边界

- 复用 imports 已发布状态下的 demo、报告日期、地区筛选索引，以及现有上传归属和任务索引。
- `import_pathogens` 主键支持按上传读取检测范围；增加 `(pathogen_code, import_id)` 支持筛选覆盖范围。
- samples 的格式 2 唯一索引支持同上传按 sam 定位，复合唯一约束支持明细归属外键。
- sample_detections 主键支持按样本取检出集合；增加 `(pathogen_code, sample_id)` 支持病原体核对与诊断。
- 组合表主键以 import_id 开头，优先在日期/地区过滤后的上传范围内聚合。GIN 数组索引仅在查询计划证明确有收益后增加，不作为首版默认成本。
- 不新增分区、Redis 或独立分析数据库。组合数最坏可接近样本数，不能保证固定压缩比。
- 延续项目“本阶段不做千万条造数及并发压测”的决定；千万级容量、P95 和导入时限仍是未验证目标，不因本设计宣称已满足。

## 4. Excel 契约、校验与导入

### 4.1 Sheet1：样本结果

必需列为 `batch`、`sam`、`PathogenWithReads`，继续兼容当前这些字段的中文及英文别名。`CT value` 和中文名称列作为可选附加字段。sam 按文本读取并保留已有前导零，去除首尾空白；不能从数值单元格恢复已经丢失的前导零，因此模板要求该列使用文本格式。

- `PathogenWithReads=N`：此 sam 为全阴性；不产生任何阳性明细。
- `PathogenWithReads=具体代码`：此 sam 检出该病原体；代码必须存在于 Sheet2。
- 同一个 sam 可有多行不同代码；sample 唯一，结果行不唯一。
- 同一 sam 的 N 与具体代码并存、重复 N、重复 `(sam, 病原体)`，无论 CT 是否相同均报错；不自动去重。
- 同一 sam 出现不同 batch 报错，不拆成两个样本以掩盖冲突。
- 具体代码行的 CT 可为空、`-`、`—` 或有限数值；空和横线仅表示未提供 CT，不改变“该行声明检出”的含义。`阴性`、待复核和其他非数值文本与阳性行冲突，拒绝导入。
- N 行 CT 可为空、横线或“阴性”；出现数值等冲突内容报错，避免把 N 标记与旧数值判定规则混用。
- 不引入临床 CT 阈值、从 CT 推断病原体、或隐藏的对照行自动剔除机制。文件应是业务需要纳入统计的样本结果。

### 4.2 Sheet2：本次检测范围

每个病原体一行。必需代码列采用 `PathogenWithReads`，接受 `pathogen`、`病原体代码` 别名；可选名称列采用 `中文`，接受 `病原体名称`。这是建议采用的新模板契约，而不是对尚未提供的真实文件布局的推断。

- Sheet1、Sheet2 均必须存在，按名字读取，不回退到任意其他表；其他表忽略。
- Sheet2 非空，代码非空、唯一，不允许 N；名称与已有字典冲突时报出 Sheet2 行号，不静默改写历史字典。已知代码未填写名称时沿用字典名；新增代码未填名称时以代码展示。
- Sheet1 中的可选名称保留原值；若与同一代码的 Sheet2 名称不同，提示警告，身份和展示名称以代码及字典为准。
- 代码大小写敏感，去除首尾空白；不擅自把不同代码合并。标识和名称长度延续现有 200 字符上限。
- Sheet2 最多 1,000 条非空数据行，作为解析资源上限；Sheet1 仍最多 30,000 条非空数据行，包含 N 行，不含表头。
- 继续使用当前文件体积、ZIP 解压、独立解析线程内存与超时限制；两个 Sheet 都受整体资源上限约束。

### 4.3 数据流和错误反馈

1. 接收文件，创建当前持久化任务；原文件仍只在排队和解析期临时保存。
2. 先解析 Sheet2，再解析 Sheet1；校验后输出显式 `formatVersion: 2`、检测范围、去重后的样本、阳性明细及摘要。
3. 解析错误标明工作表、行号和原因，整份文件不进入待确认状态；不接受部分成功。
4. 预览返回工作表列表、样本数、阳性样本数、阴性样本数、检测病原体种数、检出病原体种数、结果行数和阳性率，不返回检测明细。
5. 确认任务在单个事务内检查权限和发布状态，批量写入字典、检测范围、样本、阳性明细，校验跨表约束，生成两类汇总，更新发布状态及 dataset_state.revision。
6. 仅事务提交成功后报告提交成功；重试同一上传不会重复写入或计数。不同上传继续独立累计。
7. 待确认结构化数据仍保留 7 天；解析结束后删除原 Excel；历史摘要长期保留。

作废沿用整批状态变更与审计；所有统计查询必须以已发布上传集合为入口，不直接读取未过滤状态的汇总表。汇总重建继续采用写入协调机制和事务一致性，不暴露半成品。

## 5. 统计语义

设 S 为筛选病原体集合，P 为某上传 Sheet2 声明的检测范围，D 为某样本实际阳性集合。

- 未筛选：所有满足日期、地区、发布状态、数据来源及新格式条件的样本进入统计；D 非空为阳性。
- 已筛选：满足 `P ∩ S ≠ ∅` 的上传进入统计；样本满足 `D ∩ S ≠ ∅` 为阳性，其余计为“所选病原体未检出”，这里仅评价实际检测过的所选项目。检出非所选病毒不使该样本在此筛选下成为阳性。
- 只有 `P ∩ S = ∅` 的上传不进入分子或分母，单独返回 `excludedNoSelectedTest`，含义为“未检测任何所选病原体的样本数”。当 S 为空即查看全部时，此数为 0。
- rate = positive / samples；samples 为 0 时 rate 为 null，前端显示“—”。`notDetected = samples - positive` 表示已纳入统计但没有命中所选病原体的样本数；查看全部时才与全阴性样本数一致。
- 新格式 eligible 集合中 tested 等于 samples，表示至少检测过一种所选病原体；untested 为 0，暂留旧字段兼容内部消费者。上述数字不表示所有所选病原体都已检测，也不把未测项目填为阴性。
- 统计跨上传相加计数后再计算比例，不平均批次阳性率。

查询流程先建立地区/日期/状态/来源/版本的上传集合，再通过 `EXISTS` 在 import_pathogens 上检查是否检测过任一所选病原体，避免直接 JOIN 多个命中项导致同一上传重复。全部和单选读取 import_metrics；多选对每个符合条件的上传累加一次总样本数作为分母，读取实际组合汇总，以数组交集判断命中并累加 sample_count 作为分子。多选既不能相加单病原体阳性数，也不能相加单病原体 tested；两者都可能重复计算同一样本。不将全量明细加载进 Node 去重。

总览、地图、监测区域、排行、病原体种数和时空分布采用相同的有效上传及“至少检测一项”规则。排行与时空分布展示这个统计人群中各病原体的阳性样本数，单项计数可合计超过总阳性样本数，不应再合计为总览。各单病原体行的 tested 只累加该人群中实际检测过该病原体的上传，不直接使用整个多选人群总数作为每个病原体的分母。筛选候选病原体由当前地区/时间的检测范围字典生成，独立于已选集合，确保已选后仍能添加未检出或其他病原体。

总览与地图沿用当前选中月份/日期窗口；时空分布沿用现有 overview 的全时间窗口，显示该地区和病原体筛选下的月度分布，并明确标注“全部报告月份”。二者共享地区与病原体规则，但其日期窗口本来不同，不能把全时间图误标为当前月份统计。

`extent` 继续为当前数据来源下可用新格式数据的全局日期边界，用于时间导航，不因为选中病原体零阳性而缩短日期轴。热力图补齐边界范围内的月份；无覆盖为无数据，有覆盖无检出为 0，不能统一填 0。

### 5.1 可核对的示例

上传 A 检测 IAV、RSV、ADV：S001=N；S002=IAV 和 RSV；S003=ADV。全部为 2/3，IAV 为 1/3，IAV+RSV 为 1/3，IAV+ADV 为 2/3。

上传 B 只检测 IAV：S004=N；S005=IAV。合并查看全部为 3/5，IAV 为 2/5；IAV+RSV 为 2/5，A 和 B 均纳入，S002 与 S005 各计一个阳性样本。单选 RSV 为 1/3，B 的 2 份样本因为完全未检测 RSV 而排除。

再加入上传 C，仅检测 ADV：S006=ADV。此时查看全部为 4/6；IAV+RSV 仍为 2/5，C 被排除并提示 1 份样本未检测任何所选病原体；IAV+ADV 为 4/6。A 的 S003 在 IAV+RSV 筛选下虽检出 ADV，也仅计为所选项目未检出，样本本身的 has_positive 状态不变。

仅有 N 行的合法文件允许发布：样本数大于 0，阳性数为 0，全部病原体排行计数为 0，阳性率为 0%，不是“没有有效数据”。

## 6. API 与前端

### 6.1 接口契约

- `GET /api/dashboard` 使用重复参数表达集合，例如 `pathogen=IAV&pathogen=RSV`；单个旧参数自然等价于单选。缺省或仅空值表示全部，空项剔除、去重、排序，规范化后用于请求身份与查询。
- 不再使用 `Object.fromEntries` 丢弃重复参数；从 URLSearchParams.getAll 读取并校验，服务端参数化查询。未知病原体代码返回明确错误，已知但当前范围没有覆盖返回无数据。
- 返回 `selectedPathogens`、`pathogenOptions`、`metrics.regions`、`metrics.notDetected`、`metrics.excludedNoSelectedTest`。metrics.samples/tested/positive/rate 延续现有结构但遵守新口径；submissions 保留上传次数含义，不冒充地区数。notDetected 不命名为 allNegative，避免把部分检测的未检出结果误称为全部所选病原体阴性。
- `pathogenOptions` 以基础日期/地区集合的检测范围生成；只选择正数排行无法发现零阳性病原体，因此不能用排行替代选项。
- Preview 增加 `sheets` 与 `formatVersion`，摘要显式区分 `testedPathogens` 和 `detectedPathogens`。历史与任务恢复必须能识别版本；旧记录不以新列名重新解释。
- 热力图增加每项 tested，使“未覆盖”和“测过但零阳性”可区分。保留当前 `trend` 月度数据供热力图等现有消费者使用，本次只删除趋势图组件，不盲目删除接口字段。
- 若以后引入缓存，键必须包含版本、数据来源、日期、地区、排序后的选择集合与数据 revision；本次不为尚不存在的缓存增加新组件。

## 7. 数据演进与上线条件

当前 `server/schema.sql` 已是带校验和的版本 1 迁移，不能直接修改该文件来升级已部署库。新增版本化迁移，扩展迁移与 schema 验证到所需版本；空库必须依次应用同一套版本。

1. 结构迁移为现有 imports/samples 填充 format_version=1，保留全部旧表、记录、状态和审计；创建新范围、明细、组合表以及新格式约束，不猜测旧检测范围。
2. 迁移前盘点格式 1 的真实已发布数据和未结束任务，在写入维护期间备份并完成演练。旧解析/提交任务须先完成或取消，禁止旧暂存 payload 被新发布器当作格式 2 接收。
3. 原 N 行已被旧系统丢弃，原 Excel 也不长期保存，数据库本身不能恢复漏掉的全阴性样本。必须由持有原文件的业务方提供含完整结果和检测范围的双 Sheet 数据，按对应上传逐批重新导入，并作废被替代旧批次；保留旧新上传的迁移对应记录供核对。
4. 新口径正式启用的前置条件为：没有仍需纳入统计的格式 1 真实已发布批次、所有替代批次与原始文件核对完成、旧格式待处理任务已清理、汇总与明细一致、恢复路径可用。
5. 如果历史文件无法补齐，则保持原有线上统计版本，不能假造阴性、静默排除旧批次、或者把旧新分母直接混算；“仅从某日期启用新口径”等业务范围变更需要另行形成明确决定，本规格不自动作此决定。
6. 演示数据可以在受控迁移中重新生成格式 2；按 demo 标识处理，不影响真实上传和账号。
7. 部署维护窗口内完成替换和核对后，再启用新版服务及大盘写入。批准本规格或实现代码均不等于已执行线上切换。

迁移回退遵循既有备份恢复机制；新版一旦接受真实写入，不可直接切回只理解旧格式的应用，必须保护新增数据。迁移不物理删除旧事实数据、原有历史摘要或审计。
