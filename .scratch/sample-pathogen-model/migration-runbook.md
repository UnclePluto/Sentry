# 双 Sheet 样本模型切换手册

本手册用于把仍含格式 1 数据的 PostgreSQL 实例切换到双 Sheet、样本维度统计。任何命令都先在隔离副本演练；生产数据库地址由当次变更单提供，不写入仓库或终端记录。

## 进入维护窗口前

1. 盘点 `format_version=1 AND demo=0` 的批次，分别列出 `published`、`staged`、`withdrawn`、`expired`、`cancelled` 数量；保存批次号、原文件归档位置、提交人和替代文件负责人之间的对应表。
2. 为每个仍需保留的旧已发布批次准备新版 Excel：Sheet1 包含每个样本的完整 N 或阳性记录，Sheet2 明确列出该文件全部样本共同检测的病原体。缺少原文件、完整阴性样本或检测面板时停止在准备阶段，不推测分母，也不作废旧数据。
3. 在生产备份的隔离恢复实例上完成 PostgreSQL 恢复、`npm run db:migrate`、SQLite 导入（若需要）和本手册全流程。验证恢复耗时、回退入口和新旧批次对应表。
4. 记录当前应用镜像、数据库备份标识、迁移校验和、维护窗口负责人及回退负责人。确认新版一旦接受真实格式 2 写入，不能直接切回会忽略这些事实的旧应用。

## 维护窗口执行

1. 暂停展示入口和普通管理入口，只保留受控管理员连接；停止旧 API 与旧工作进程，确认没有运行中或持有租约的任务。
2. 开启数据库维护状态。`maintenance=true` 会阻止工作进程领取任务，所以不能在此状态等待新版重导入完成。
3. 创建并校验即时备份。对旧 SQLite 来源先生成私有一致性快照；导入脚本只接受空目标库，第二次运行会拒绝覆盖。
4. 应用版本化数据库迁移并部署新版 API、管理端和工作进程。旧有效待确认任务迁移为 `cancelled`，提示“旧格式预览请重新上传”；旧 payload 保留为不可发布的审计数据，原 SQLite 私有快照继续保留。旧过期任务保持 `expired`。
5. 保持展示入口暂停，关闭数据库维护状态，使新版工作进程可以处理格式 2 上传。由管理员按对应表逐批上传替代文件；每批发布并核对样本数、阳性/阴性样本数、检测范围和阳性组合后，才作废对应旧批次。
6. 对所有格式 2 已发布批次重建贡献，逐样本抽查多阳性去重、全 N、零阳性和不同检测范围。运行只读预检：

   ```bash
   node scripts/postgres/check-sample-model.mjs
   ```

   只有输出 `{"ready":true,"publishedLegacy":0,"unfinishedLegacy":0}` 且退出码为 0 才能继续。退出码 2 表示仍有旧真实已发布或待确认批次；不得用日期或地区筛选绕过。

7. 运行完整测试、类型检查、lint、生产构建和针对隔离服务的 smoke。人工验证真实大盘、双 Sheet 上传、历史/作废、普通管理员权限、超管权限、演示数据和 503 保护。
8. 恢复展示入口和正常管理访问，持续观察请求失败、任务队列和数据库连接。保存预检 JSON、测试结果、批次对应表和验收人记录。

## 中止与恢复

- 替代文件不完整、备份校验失败、迁移校验不一致、预检未就绪或样本核对不一致时，保持展示暂停并停止继续作废旧批次。
- 尚未接受任何格式 2 真实写入时，可按演练步骤恢复维护前备份与旧镜像。
- 已接受格式 2 真实写入后，先保护新事实、上传审计和原文件，再执行已演练的数据前向修复或合并恢复；不得直接恢复旧备份覆盖新写入。
- 503 是误切换保护。它只阻止新版真实大盘，管理登录、历史、作废、新上传和演示大盘仍可用于完成处置；不应把 503 当作长期运行状态。
