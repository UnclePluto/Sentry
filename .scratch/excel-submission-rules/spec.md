# Excel 提交、统计口径与历史管理重构

Status: ready-for-agent

日期：2026-09-15

说明：业务规则来自本次已确认的访谈。用户已确认使用真实 HTTP 接口与临时数据库作为主要测试边界，并采用本地 Markdown 作为项目 Issue 跟踪方式。本规格已正式发布；`ready-for-agent` 表示可进入后续实现流程，本轮不修改业务代码。

## Problem Statement

管理员需要按整份 Excel 提交和管理检测数据，而当前系统要求先维护检测机构，上传后提供检测明细和原文件下载，并跨提交选择最新样本覆盖旧结果。这与实际按上传批次独立累计、整批作废的工作方式不符。

当前统计还把部分对照数据保留为未检测或阴性，无法满足“CT 为横线或病原体为 N 即剔除”的口径。部分数据只能定位到市，不能人为分配到区县，否则地图下钻会产生不真实的分布。此外，后台缺少提交归属控制，普通管理员不应看到或作废其他人的提交。

## Solution

管理员选择检测日期、至少到市的行政区划，上传 Excel。系统只读取 Sheet1，先剔除对照行，再校验有效记录和本次文件内的重复结果。通过校验后只展示汇总，管理员确认提交才正式计入大盘。原 Excel 在解析结束后不保留。

每次上传产生独立的业务上传批次，批次之间不去重、不覆盖。历史列表以整份提交为管理单位，记录提交人、时间、地区、有效数据汇总与状态；作废后整批退出统计，历史仍可追溯。管理员只管理自己的提交，超管管理全部提交。前台保持面向用户的独立汇总大盘。

## User Stories

1. 作为上传管理员，我希望直接选择行政区划，以便不必先创建检测机构或填写坐标。
2. 作为上传管理员，我希望至少选择到市，以便无法定位区县的数据仍可提交。
3. 作为上传管理员，我希望可以继续选择区县，以便精确的数据参与区县分布统计。
4. 作为上传管理员，我希望手动选择整份文件的检测日期且默认当天，以便补录历史检测数据。
5. 作为上传管理员，我希望系统自动记录提交时间，以便区分检测发生时间和录入时间。
6. 作为上传管理员，我希望系统只读取 Sheet1，以便其他工作表的备份和辅助数据不参与统计。
7. 作为上传管理员，我希望缺少 Sheet1 或必要列时收到明确错误，以便修正文件后重新上传。
8. 作为上传管理员，我希望 batch 保持原有检测批次含义，以便它与系统上传批次号不会混淆。
9. 作为上传管理员，我希望 sam 表示试剂标识，以便同一试剂的多个病原体结果正确归组。
10. 作为上传管理员，我希望病原体代码及其中文翻译正确关联，以便大盘使用可读的病原体名称。
11. 作为上传管理员，我希望 CT 为横线的行被剔除，以便污染判断用的对照试剂不污染统计。
12. 作为上传管理员，我希望病原体为 N 的行被剔除，不论其 CT 内容，以便统一排除这类数据。
13. 作为上传管理员，我希望数值 CT 被识别为阳性、“阴性”被识别为阴性，以便结果符合约定口径。
14. 作为上传管理员，我希望有效记录中空白或无法识别的 CT 被指出行号，以便修正后再提交。
15. 作为上传管理员，我希望同一试剂对应不同病原体的行可以提交，以便保留多病原体检测结果。
16. 作为上传管理员，我希望本次上传中 batch、sam 和病原体三项相同的有效行被拦截，以便避免重复计数。
17. 作为上传管理员，我希望对照行先被剔除再检查重复，以便重复对照行不会阻止有效数据上传。
18. 作为上传管理员，我希望重复结果即使检测值相同也不能自动去重，以便由提交人负责修正原始数据。
19. 作为上传管理员，我希望解析后看到有效试剂数、阳性试剂数和剔除行数，以便提交前核对数据规模。
20. 作为上传管理员，我希望确认前数据不参与大盘统计，以便错误的预览不会影响用户。
21. 作为上传管理员，我希望没有有效数据的文件不能提交，以便避免空批次进入历史记录。
22. 作为上传管理员，我希望每次正式提交拥有唯一上传批次号，以便定位整份 Excel 对应的数据。
23. 作为上传管理员，我希望各上传批次独立累计，以便系统不擅自覆盖其他已提交结果。
24. 作为上传管理员，我希望原文件解析后不留存且后台不提供检测明细，以便只维护必要的结构化数据及提交汇总。
25. 作为上传管理员，我希望在历史列表看到自己的提交人信息、时间、日期、地区、有效数据和状态，以便追踪录入情况。
26. 作为上传管理员，我希望只能查看自己的提交，以便后台历史符合账号归属边界。
27. 作为上传管理员，我希望能够一次作废整份提交，以便不需要逐条处理错误结果。
28. 作为上传管理员，我希望作废后仍能看到原汇总及作废时间、操作人，以便追溯处理过程。
29. 作为超级管理员，我希望查看所有人的提交，以便统一管理数据录入情况。
30. 作为超级管理员，我希望能作废任何管理员的提交，以便处理错误或重复上传。
31. 作为大盘用户，我希望总览按有效试剂而不是结果行计数，以便同一试剂的多个病原体不会扩大检测总数。
32. 作为大盘用户，我希望同一试剂只要任一病原体阳性就计为阳性试剂，以便阳性率口径一致。
33. 作为大盘用户，我希望各病原体检出分别统计，以便多病原体阳性能够反映在对应排行中。
34. 作为大盘用户，我希望全国及省级视图包含市级和区县级提交，以便查看完整汇总。
35. 作为大盘用户，我希望市内区县视图只包含明确归属区县的数据，以便地图不虚构位置。
36. 作为大盘用户，我希望两侧图表与地图采用相同地区范围，以便下钻后各模块的数据一致。
37. 作为大盘用户，我希望日期筛选和时间播放使用检测日期，以便历史分布不受补录时间影响。
38. 作为大盘用户，我希望作废批次退出所有相关统计，以便看到当前有效数据。
39. 作为维护者，我希望演示数据遵循相同的新规则且仍与真实数据隔离，以便演示能够代表真实业务行为。

## Implementation Decisions

### 领域术语及计数单位

- 检测批次号：Excel 的 batch，一批检测的标识，不作为系统上传提交号。
- 试剂标识：Excel 的 sam；同一上传批次内以 batch + sam 识别一个试剂。
- 病原体：PathogenWithReads 中的代码；中文列为对应翻译，不参与重复键。
- 上传批次：业务系统对一次提交分配的唯一标识，归属一个提交管理员、一组行政区划和一个检测日期。
- 病原体结果：一个试剂对一个病原体的有效结果。唯一性范围为上传批次 + batch + sam + 病原体。
- 有效试剂：剔除对照行后至少剩余一条有效结果的试剂。有效结果行数与有效试剂数分别记录，不混称“数据量”。
- 阳性试剂：至少有一条有效阳性结果的有效试剂。总览阳性率 = 阳性试剂数 / 有效试剂数；分母为零显示无数据，不伪造为 0%。
- 单病原体检出数量按其阳性结果统计；存在的单病原体阳性率仅使用该病原体明确记录的有效结果，不推测缺失行是阴性。

### 解析与校验顺序

1. 保留现有 Excel 文件类型、体积、行数和解析资源限制；只查找名为 Sheet1 的结果表，缺失时明确报错，不回退选择其他表。
2. 读取必要表头和可选中文翻译，标识与 CT 文本去除首尾空白。完全空行不计结果行。
3. 先按 OR 条件剔除 CT 为 `-`／`—` 或病原体为 `N` 的行；一行同时满足两个条件只计一次剔除。
4. 对剩余行检查必要标识和 CT：有限数值视为阳性，“阴性”视为阴性；空白、非数值异常文本等阻止整个文件提交。不增加新的临床 CT 阈值规则。
5. 在剩余有效行内，按 batch + sam + 病原体检查重复。无论检测值相同或冲突，都阻止提交并给出重复组合与行号；不同病原体允许共享 batch + sam。其他工作表和其他上传批次不参与检查。
6. 有错误时不允许部分入库；全部剔除或没有有效试剂时不允许确认提交。解析完成后仅保留结构化数据，不保留原 Excel 文件。
7. 中文列参与名称映射，其他工作表不再作为字典来源；现有已知病原体名称映射可以沿用。名称不得影响代码身份或计数。

### 提交状态与文件生命周期

- 采用“待确认 → 已提交 → 已作废”的单向业务流程。预览仅返回汇总和校验提示，不返回逐条检测结果。
- 确认提交前不进入任何大盘统计；确认时原子地写入有效结构化数据及提交归属、检测日期、地区和汇总。
- 上传批次号独立于 Excel batch。两次独立上传即使文件相同也可以形成两个提交并分别累计；取消原有相同文件拦截和跨提交最新版本覆盖。
- 同一个待确认批次被重复点击确认时不能重复累计；这与允许两次独立上传分别计数是两件事。
- 新上传流程不持久化原 Excel 字节；解析失败也不能留下原文件。为确认提交保留的结构化待确认数据不等于保留 Excel。
- 移除原文件下载和逐条检测明细入口及其对应可访问能力。标准化检测结果仍由服务内部保存，用于统计及整批作废。

### 地区与大盘统计

- 提交直接保存省、市及可选区县的代码和名称，不再依赖检测机构实体或经纬度。地区上下级关系由服务端校验，不能只靠页面选择器约束。
- 全国视图按省展示；省级视图按市展示，两者均纳入所属市级及区县级提交。
- 进入某市的区县分布视图后，仅纳入该市明确填写区县的提交；市级提交不均摊、不指派到某区，也不放置虚构点位。
- 区县作为最细数据归属层级，停止原有向机构点位继续下钻的业务路径。
- 直辖市可在其市级归属下提交，区县可选；当地图直接显示其区县分布时，同样排除未填写区县的提交。
- 总览、排行、趋势、时空分布和地图使用一致的地区数据集合，继续遵循各模块既有的时间展示方式。下钻后因剔除市级数据而减少总量是预期行为。
- 检测日期是筛选和时间播放的时间依据；提交时间只用于历史追溯。
- 汇总来自所有已提交且未作废的上传批次，管理员个人历史可见范围不限制公共大盘数据。

### 历史、归属与作废

- 上传批次保存提交人账号标识及可追溯的名称信息、提交时间、检测日期、地区、原始文件名、有效结果行数、有效试剂数、阳性试剂数、剔除行数和状态。保存文件名不代表保存文件内容。
- 历史列表以整份提交展示，不提供检测细节。已作废记录保留原提交汇总，并记录作废时间与操作人。
- 普通管理员只能读取和作废本人批次；超管可以读取和作废所有批次。待确认数据及确认操作也必须校验归属，不能通过猜测批次号越权。
- 提交人来自当前登录会话，不接受客户端任意指定。API 层强制执行归属检查，不以隐藏按钮代替授权。
- 作废操作整批生效，不删除历史记录；重复作废不重复扣数。作废不会触发旧版本恢复，因为新模型不存在跨提交版本覆盖。
- 作废后的查询立即按新有效集合计算；前台在后续数据刷新时更新，不在本规格中引入实时推送系统。
- 沿用现有超管账号管理和登录能力；账号改名、停用或删除不能使既有提交审计信息丢失或删除检测历史。

### 模块与数据演进

- 修改 Excel 解析模块、提交管理与存储模块、统计聚合模块、后台上传及历史界面，以及前台行政区下钻的数据筛选。
- 提交数据结构增加地区归属、提交人及作废审计信息；试剂身份以上传批次为边界；汇总读取所有有效批次，替换按机构和最新日期选择结果的旧逻辑。
- 上传预览接口改为接收行政区划与检测日期，响应只含批次标识、汇总及校验反馈；确认、历史及作废接口统一实施归属校验。
- 管理入口移除机构维护、逐条检测明细和原文件下载。前台与后台继续保持独立入口。
- 当前本机核查只有 96 条已发布演示提交、没有真实提交，旧提交结构没有提交人字段。同步迁移或重建演示数据以符合新模型，保留演示与真实数据隔离；不把演示提交虚构为真实管理员上传。
- 数据升级应可重复执行，不破坏已有账号。旧规则的说明和测试预期同时更新，不能继续引用旧样表的总数作为新口径结论。
- 如果实施时发现新增真实旧提交，按此前确认原则处理：能够确定归属和地区的按新口径处理，无法确定归属的保留为已作废历史，不猜测提交人；删除历史原附件之前先完成必要的结构化迁移核对。

## Testing Decisions

### 已确认的主要测试边界

沿用现有真实 HTTP 接口集成测试：启动真实数据服务，使用临时 SQLite 数据目录，通过真实管理员会话上传生成的 Excel，完成预览、确认、查询大盘、查看历史、整批作废以及重启后的持久化验证。

这是主要验收入口，贯穿解析、存储、统计和权限，不另建多组针对内部函数或 SQL 写法的测试。测试只断言外部可见行为和业务结果，不固定内部实现。现有登录权限测试与上传闭环测试提供先例；文件不留存的要求额外检查临时数据目录，因为仅测 HTTP 不足以证明磁盘没有残留。

### 必须覆盖的验收场景

1. 仅有 Sheet1 时正常解析；Sheet1 缺失报错；其他工作表包含重复或非法数据不影响 Sheet1。
2. CT 为横线但病原体正常、病原体为 N 但 CT 为数值或阴性、同时满足两项，均正确剔除且不重复计数。
3. 被剔除行重复不阻止提交；有效行三元组重复无论值相同还是冲突均阻止；同一试剂不同病原体合法。
4. 有效行的 CT 空白或异常文本、必要标识缺失时整份失败，提示 Sheet1 行号；零有效数据不能确认。
5. 构造有效试剂 A（甲、乙均阳性）及 B（甲阴性）：有效结果 3 行、有效试剂 2、阳性试剂 1、总览阳性率 50%，甲乙检出数各 1。加入对照行不改变上述统计。
6. 预览不改变大盘；确认后才计入。同一预览重复确认不重复计数。
7. 将上述文件独立上传两次，统计变为有效试剂 4、阳性试剂 2；作废其中一份后恢复为 2 和 1，另一份保持有效。不同检测日期的提交同样不覆盖。
8. 同一市分别提交市级和区县级数据：全国及省级均计入两份，市内区县视图只计区县级份额，相关图表一致；返回上层恢复完整统计。覆盖直辖市对应场景。
9. 检测日期与提交时间不同，验证日期筛选依据检测日期，历史分别展示两个时间。
10. 管理员 A 和 B 分别提交，双方列表只显示自己的批次；直接请求对方批次的确认、读取或作废不能成功；超管能查看和作废两人的批次。
11. 作废前后历史汇总保持可追溯，新增作废时间与操作人；重复作废不重复扣数，重启后状态和统计不丢失。
12. 成功及失败解析均无原 Excel 留存，原下载和检测明细能力不可访问，汇总响应不泄漏逐条数据。
13. 账号停用、删除或改名后，提交历史仍有可辨识的原提交人信息；演示与真实数据仍隔离。
14. 升级后的演示数据遵守新统计口径，重复启动不重复生成或累计；既有账号可继续使用。

界面验收补充覆盖行政区选择、汇总确认、本人/全部历史和作废反馈，以及前台下钻范围变化。类型检查、构建和现有入口隔离检查用于集成回归，不扩展为本次未要求的地图视觉重设计。

## Out of Scope

- 实际业务代码实现、部署和公网发布不属于本次规格编写步骤。
- 跨上传去重、版本覆盖、自动识别纠错文件、作废后恢复旧版本。
- 检测机构、具体点位、经纬度录入及区县以下地图点位。
- 逐行修改或作废、检测明细展示、原文件长期保存与下载。
- 读取 Sheet1 之外的工作表、多工作表合并或人工选择结果表。
- 临床阳性阈值判定、病原体风险分级、根据缺失行推定阴性。
- 新的复杂角色体系、按机构隔离大盘、审批流和实时推送。
