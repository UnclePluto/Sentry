# PostgreSQL 生产架构、异步导入与可恢复部署

Status: ready-for-agent

日期：2026-09-16

发布位置：项目本地 Markdown 议题库。业务及架构约束已由用户逐项确认；用户已确认本规格测试边界，现正式发布为 ready-for-agent。规格编写不包含业务代码实现、部署切换或资源购买。

## Problem Statement

Sentry 已经用于线上病原体监测，但当前 SQLite 单文件存储、大盘全量读取明细后在应用内存中统计、依附 HTTP 请求的解析流程，无法作为用户期望的可扩展生产架构。上一轮同域名后台路由改造也出现了接口测试通过、实际浏览器登录失败的遗漏，后续验收必须覆盖用户真实入口。

管理员需要多人上传 Excel、离开页面后继续处理、可靠确认入库及整批作废。系统必须保护已有账号、检测结果及审计历史，并在服务重启、网络重试和恢复备份后维持相同统计口径。用户希望以累计 1,000 万条有效检测明细为首阶段设计规模，但暂时保留现有 2 核 2 GB ECS，且本阶段明确不做容量和并发压测，不能把设计目标写成已验证能力。

生产数据需要独立于 ECS 保存备份，能够在故障后恢复。当前没有外部告警渠道，故障发现依赖人工检查，因此容量、可用性和恢复能力必须分别报告实施状态与验证证据。

## Solution

以 PostgreSQL 替换运行时 SQLite，统一保存业务数据、账号会话、持久化导入任务和统计汇总。保留当前大盘及管理后台的使用入口、地图交互和已确认的统计口径。

管理员上传文件后立即获得可追踪的任务，后台工作进程按资源限制排队解析。解析成功后删除原 Excel，仅保留待确认的结构化数据及校验汇总；管理员可在 7 天内确认。系统显示正在提交，直到检测结果与统计汇总完整提交后才提示成功；重试不重复计数。大盘从汇总数据读取结果，上传确认或作废成功后在 30 秒内更新。

首阶段应用、工作进程和 PostgreSQL 共用现有 ECS，首版不引入 Redis、MongoDB、RDS 或额外数据库服务器。数据库基础备份及持续归档日志保存到指定 OSS 私有 Bucket 的专用目录，保留最近 30 天的恢复链。迁移时允许短暂冻结写入，完成备份、数据核对和切换，保留明确的回退路径。

## Implementation Decisions

### 1. 架构与资源边界

- 采用 PostgreSQL 作为唯一运行时业务数据库；SQLite 只作为一次性迁移源及受控回退备份，不保留运行时自动降级或双写路径。
- 保持一个业务系统，区分 Web 展示与管理、业务 API、独立后台工作进程和 PostgreSQL 的职责，不扩展为分布式微服务体系。模块可独立测试，API 与工作进程通过持久化状态协调，数据库连接配置外置，便于后续分机部署。
- 首版不引入 Redis。任务不能仅存在于进程内存，会话不能依赖某个 Web 进程的本地状态。
- 使用有上限的连接池、连接与语句超时、事务以及参数化查询；同一事务必须使用同一数据库连接。迁移采用版本化、可检查的数据库演进流程，多进程启动不得并发重复迁移或生成超管。
- PostgreSQL 不开放公网访问。业务账号采用所需最小权限，数据库管理、迁移和备份身份与运行时职责区分；密码和 OSS 凭据由部署环境安全注入，不进入源码、镜像或日志。
- 在现有 2 核 2 GB ECS 上限制应用、工作进程和数据库资源。首版解析并发以单任务为保守实现起点，其他上传持久化排队；这是资源配置默认值，不是已经压测的容量结论。提交、清理、归档和备份任务同样不能无界并发。
- 就绪检查验证数据库及所需迁移可用，运行状态可检查工作进程和归档健康。采用可控重启、优雅退出和任务恢复，不将接口进程退出等同于任务丢失。

### 2. 保持不变的业务口径

- 上传批次与 Excel 检测批次严格区分。试剂由同一上传批次内的 batch 与 sam 标识；有效结果唯一键再加病原体代码，中文名称不参与身份判断。
- 只处理 Sheet1；缺少必要工作表、表头或有效数据，不能确认入库。文本规范化、富文本去首尾空白、数值 CT 阳性及“阴性”判定沿用现有规则。
- CT 为横线或病原体为 N 采用 OR 条件先剔除，再校验剩余有效行。有效行重复或非法阻止整份提交，不能自动去重、忽略异常或部分入库。
- 单文件最多 30,000 行检测数据，不含表头，包含最终剔除的对照行；完全空白行不算检测数据。实现还须限制文件字节量、解压及解析资源，不能只靠有效结果行数防止资源耗尽。现有 8 MiB 上传限制暂沿用为实现默认值，独立于 30,000 行上限；若实际最大合法样本无法兼容，须明确报告，不静默放宽或宣称所有 3 万行文件都能上传。
- 报告地区至少到市、区县可选；服务端校验层级。市级提交纳入全国和省级统计，进入市内区县分布时排除，直辖市同理。地图及相关图表使用相同地区集合。
- 总览以有效试剂计数，任一病原体阳性即为阳性试剂；不能将各病原体试剂数相加当作总览，也不能直接平均阳性率。按病原体保存独立分子分母以支持筛选；不将缺失病原体结果推定为阴性。
- 不同上传批次独立累计，即使文件内容相同也不跨上传去重或覆盖。演示与真实数据继续隔离；大盘数据范围不受管理员个人历史可见范围限制。

### 3. 数据模型与统计读取

- 保留上传批次、试剂、病原体及检测结果、账号与会话、提交与作废审计，增加持久化任务、任务尝试与租约、待确认有效期、统计汇总和可追踪数据版本。
- 检测明细、正式提交及作废审计长期保存。暂存记录、原文件和运行日志有独立清理规则，不得连带删除正式数据。
- 明细是可重建汇总的依据；大盘常规请求读取 PostgreSQL 中的持久化统计汇总，禁止将匹配的全量检测明细加载进 Node 再分组。
- 汇总以上传批次为可追溯贡献边界，保留报告日期、地区粒度、真实／演示标识，以及总体试剂和各病原体分子分母；可在数据库内进一步按日期、地区及病原体聚合。具体物理表和索引由实现设计，不在本规格要求现在就采用分区或独立分析数据库。
- 正式确认在单个原子事务中完成正式结果、汇总贡献和发布状态的一致提交；批量写入，不对每一行单独提交事务。作废原子更新有效状态与统计贡献，重复操作不重复增减。
- 汇总重建必须有版本或其他一致性切换机制，不能向大盘暴露一半新、一半旧的汇总；重建后核对总体、地区、日期、病原体结果。
- 查询索引覆盖身份唯一约束、任务领取、有效批次的日期及地区筛选、病原体、归属历史和有效期清理。列表分页且响应有上限，不能把所有历史及任务一次返回。
- 如使用短时本地缓存或请求合并，必须保证提交与作废后的 30 秒端到端可见时限，且重启不影响事实数据；缓存不是必须引入的组件。不允许缓存时长、后台处理和前端轮询各自独占 30 秒。

### 4. 异步导入、接口及状态

- 上传接口校验登录、报告日期、地区、文件类型及大小；完整接收并可靠暂存文件、登记任务后返回已受理状态及任务标识，不把“已受理”称为“已入库”。上传未完成或暂存失败不返回受理成功。
- 上传任务绑定发起人和上传批次；提供有归属校验的状态查询、分页任务列表、汇总结果查看和允许状态下的取消／重试操作。普通管理员只能访问自己的任务，超管可以访问全部；直接调用接口同样校验权限。
- 前端状态包含排队、解析中、待确认、正在提交、已提交、失败、已取消、已过期和已作废等用户可辨别阶段，任务状态与正式批次状态分开建模。失败需标明解析或提交阶段、是否可重试及用户下一步，不用虚构百分比表示进度。
- 工作进程通过数据库事务安全领取任务，使用可过期租约、所有者标识和有界重试恢复故障。旧进程恢复后不能覆盖已由新进程接管的结果；业务副作用使用幂等机制，而非声称任务永不重复执行。
- 解析不占用 API 事件循环；服务重启后继续排队任务，租约超时任务可接管。业务校验失败应要求修正文件，不做无限自动重试；基础设施暂时故障可以有界重试。
- 原文件仅在排队和解析期间存放于服务端私有目录，无公开下载入口，不纳入长期备份。解析成功、校验失败或取消后删除；异常遗留自文件接收起最长保留 24 小时，到期任务明确失败，不能永远挂起。删除失败要记录并重试。
- 数据库任务与本地文件不能假设天然原子：覆盖上传中断、写文件后登记失败、文件缺失及重启对账。数据库恢复后若排队任务对应原文件不存在，明确失败并要求重传；这不属于已确认业务数据丢失。
- 待确认结构化数据自校验结果生成起保留 7 天，到期清理暂存明细，保留摘要并标记过期。到期清理与确认使用互斥状态变更，不能清理已被提交处理可靠接管的数据；在截止时间前未被接受的确认应提示过期。
- 确认接口验证归属、账号权限及有效期，可靠登记提交处理后显示正在提交，允许离开页面再查。请求幂等限定同一上传批次，不能用文件哈希合并独立上传。
- 正在提交期间不允许形成相互矛盾的取消、清理或作废结果；已作废批次不能重新发布。提交事务未完成不得显示成功，崩溃或重复消费不能产生部分正式数据或重复汇总。
- 暂存明细与正式明细隔离；提交失败保留允许恢复所需的数据和错误状态。重试前重新验证操作者权限，普通管理员不能借重试操作他人任务。
- 历史列表继续按整份上传批次展示提交人、报告日期、地区、有效汇总、状态及审计，不提供检测明细或原文件下载。

### 5. 前端与认证兼容

- 大盘和管理后台仍共用已配置域名，使用既有独立页面路由；大盘不增加管理入口。API、页面跳转、静态资源及反向代理前缀必须一致。
- PostgreSQL 保存登录会话并沿用现有密码哈希验证，保留账号角色和停用状态；迁移不得无条件重置超管密码或生成重复超管。现有会话可以保留或受控失效并重新登录，但不能出现旧会话绕过停用或改密。
- 上传、任务与账号页面复用完整登录状态布局，超管显示账号管理入口，普通管理员不能访问超管能力。HTTPS、安全 Cookie、来源校验、服务端授权和登录频率限制继续有效。
- 页面轮询任务状态可恢复，失败与过期有明确反馈；确认请求超时后先查询该批次状态，不直接再建一个独立上传批次。
- 保持 2D／3D 地图、下钻和自动刷新现有行为，本次只改变数据通路，不重做视觉样式。

- 指定 OSS Endpoint 为 oss-cn-shanghai.aliyuncs.com，现有 Bucket 为 oss-pai-k0brz1afnz8dtbcgt0-cn-shanghai，仅使用 sentry/postgresql/ 专用前缀。已知桶为上海标准存储、私有、同城冗余、版本控制未开启；不得擅自修改整个桶设置或影响其他前缀。
- 备份方案包含可恢复的数据库基础备份及持续 WAL 归档，目标支持最近 30 天内的时间点恢复。单独执行逻辑导出或每 15 分钟备份一次，不能替代这一目标。
- 对象命名区分环境、数据库实例及备份链，恢复工具验证清单与完整性。到期清理按恢复依赖执行，必要时保留早于 30 天边界的基础备份及关联日志；不得按对象年龄机械删除导致恢复链断裂。
- 使用加密传输及限定前缀的最小授权；凭据安全配置。OSS 身份、策略及网络可达性尚未提供，需要实施时完成；不得因已有 Endpoint 和 Bucket 就宣称备份已接通。

- RPO 目标最多丢失 15 分钟已成功提交的数据；RTO 目标故障后 1 小时内恢复大盘、管理员登录及数据提交。恢复时间需包含准备替代运行环境、取回备份、回放日志、配置应用和核对，不能只统计数据库回放时间。
- 在隔离目标中演练备份恢复，禁止覆盖在线库。归档失败、延迟、磁盘不足及恢复链不完整必须能从日志和状态查询中识别；记录最近成功备份和可恢复时间点。
- 首版不接邮件或机器人，不做外部告警。保留可关联请求、任务、上传批次、错误阶段、尝试次数与耗时的结构化日志；不记录密码、令牌、原文件内容或检测明细正文。
- 日志必须轮转、受总量限制并有清理策略，保留期限及磁盘预算配置化。实际数值由部署实施按现有磁盘制定并记录，不将未讨论的数值伪装为用户已确认要求。
- 单机部署且无主动通知意味着故障发现与替代资源准备仍依赖人工；仅配置备份不代表 RPO／RTO 已保障。

### 7. 迁移、切换及回退

- 迁移前以实时只读盘点为准，统计现有账号、上传批次、试剂、结果、演示标识、发布／作废状态和关键业务汇总。不能沿用早期“只有演示数据”的结论。
- 对生产 SQLite 制作一致性快照并校验完整性，保护原数据库及 WAL 相关状态；不能直接复制正在变化的单个文件就视为完整备份。先以隔离副本验证迁移流程与数据映射。
- 保留账号及密码哈希、提交标识、归属、日期、地区、原结果、作废历史和正式统计口径。尚未完成的旧预览明确映射到新状态及有效期，不得静默丢弃或自动正式发布。
- 正式切换进入维护模式，拒绝或受控暂停上传、确认、作废、账号修改及其他会影响迁移一致性的写入，停止旧工作进程与清理任务并处理在途事务。大盘尽可能只读展示，无法做到时展示真实维护状态。
- 从冻结后的快照导入 PostgreSQL，重建并核对汇总，校验数量、约束、字段、归属和各维度统计；迁移可恢复或安全重跑，不能重复导入。发现差异停止开放写入。
- 验证新库下的登录、权限、真实页面路由、任务处理和查询后再开放写入。切换方式、维护时长与回退判据在演练后记录，不能提前虚构维护时长。
- 开放新库写入前可以回退到冻结时的旧应用与快照；新库接受写入后不得直接切回旧快照。此时先冻结、保存新库数据并制定恢复／补偿方案，避免丢弃新提交。
- 旧库和切换备份保持受控只读，退出正常运行路径；不因迁移成功立即删除唯一回退来源。备份和历史保留应与安全及恢复规则一致。

### 8. 设计目标与本阶段边界

| 项目 | 已确认目标 | 本阶段验证状态要求 |
|---|---|---|
| 累计规模 | 首阶段 1,000 万条有效检测明细，长期继续增长 | 不造千万条数据压测，标记未验证 |
| 同时使用 | 最多 20 个大盘页面，1～3 位上传管理员 | 不做并发性能压测 |
| 大盘接口 | 上述规模下 P95 ≤ 2 秒，不含地图下载与动画 | 性能验收延期 |
| 单次文件 | Sheet1 最多 30,000 行检测数据 | 边界功能校验可测，不等于负载压测 |
| 解析 | 3 份最大文件同时上传，含排队最多 5 分钟 | 目标保留，负载达标未验证 |
| 确认提交 | 3 人同时确认最大文件，含排队最多 1 分钟 | 目标保留，负载达标未验证 |
| 大盘更新 | 提交或作废成功后端到端最多 30 秒 | 用小数据验证机制与正确性，不能外推大负载达标 |
| 原文件 | 正常终止后删除，异常最长 24 小时 | 生命周期功能验证 |
| 待确认数据 | 解析成功后保留 7 天 | 过期、竞争与清理功能验证 |
| 数据／备份 | 正式业务长期保留，备份恢复窗口 30 天 | 保留链算法与恢复验证，刚上线不能声称已有 30 天历史 |
| 恢复 | RPO ≤ 15 分钟、RTO ≤ 1 小时 | 演练记录实测条件和结果，未验证部分明确标记 |

## Testing Decisions

用户已确认测试边界：以真实 HTTP 接口、隔离 PostgreSQL 和实际工作进程为主要边界；补充真实浏览器关键流程及隔离迁移／备份恢复命令。本阶段不做容量或并发压测。

1. 优先测试外部可观察行为：返回状态、可查询任务状态、权限、最终汇总、重启后的结果、文件是否按规则清理及恢复后的业务数据。不要以内部函数调用次数、SQL 字符串快照或与实现相同的算法重写作为正确性证据。
2. 复用现有“启动真实 API＋临时存储”的集成测试方式，将临时 SQLite 替换为隔离 PostgreSQL 数据库及真实工作进程。测试环境不得连接生产数据库或清理生产 OSS 前缀。不同用例的数据与任务互相隔离。
3. 沿用现有账号权限测试、提交统计集成测试、可选真实样表测试和展示／管理入口隔离测试。迁移后继续验证真实样表的既有汇总基线、独立累计和整批作废；真实样表不上传到公开仓库。
4. 覆盖 Sheet1 选择、表头错误、对照 OR 剔除、富文本规范化、有效行重复、非法 CT、无有效数据、30,000 与 30,001 行边界以及文件体积限制。单文件边界测试不作为千万条或多人并发性能验收。
5. 用真实任务状态查询验证上传受理、排队、解析、待确认、确认中、已提交、失败、取消及过期的完整路径。关闭页面后重新进入应看到同一任务，而不是新建任务。
6. 通过受控停止并重启工作进程验证任务恢复、租约接管、原文件丢失、失败重试上限以及旧任务不得覆盖新结果。少量重复请求或双工作进程竞争只验证幂等和事务正确性，不是容量压测。
7. 验证确认前不可见、提交原子性、同批次并发重试只计一次、独立上传分别累计、重复作废不重复扣数，以及作废与确认／清理竞争不会产生混合状态。
8. 验证 7 天到期清理、24 小时异常文件清理及恢复后重新清理过期记录。可控制时钟或合法设置测试状态，不实际等待数天；验证最终外部行为，不锁死内部调度实现。
9. 验证总体试剂统计、病原体筛选、排行、时间趋势、各级地区和直辖市范围，包含只到市的数据；提交与作废后旧缓存失效。明细基准与重建汇总须结果相等，演示与真实数据不交叉。
10. 通过真实浏览器覆盖登录表单发出的接口、超管身份与账号管理入口、普通管理员权限、上传状态恢复、确认、历史、作废及退出。不得仅直接调用登录 API 就宣布页面登录可用；沿用此前登录路由与会话布局回归的教训。
11. 在隔离环境中从包含账号、正式与作废批次及旧预览的 SQLite 快照迁移，校验标识、数量、密码可用性、权限及多维统计。重复迁移不得重复计数；维护期间写入应被拒绝，新库放行前后分别验证回退边界。
12. 备份采用独立演练目录或隔离存储测试环境：基础备份、实际归档日志、指定时间点恢复和业务核对。必要时注入归档不可达、凭据失效或日志缺口，验证失败可识别且不删除唯一恢复链。不得在生产库上模拟破坏。
13. 没有 OSS 访问授权时可先验证本地兼容流程，但必须标记真实 OSS 备份与恢复未验证，不以模拟对象存储成功代替真实演练证据。30 天保留依赖可用控制时间的小数据用例验证，实际历史窗口随系统运行积累。
14. 检查日志脱敏、关联标识、轮转和总量限制；凭据不得进入测试输出。类型检查、生产构建和既有地图回归继续执行。
15. 本阶段不做千万条数据生成、容量上限探索、并发压力测试或扩容采购。功能验证结果不得写成 P95、最大吞吐或恢复服务承诺；报告明确区分已验证、未验证及需外部配置事项。
