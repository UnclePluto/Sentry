# 03 — 上传排队、解析与结果查看

**What to build:** 管理员上传 Excel 后获得可追踪任务，独立工作进程完成解析并展示校验汇总；关闭或刷新页面后可以回来继续查看，不需要请求一直保持连接。

**Blocked by:** 02 — PostgreSQL 登录与账号管理闭环

**Status:** in-progress

- [ ] 文件完整接收、私有暂存与持久化任务登记可靠完成后才返回受理成功；上传中断、写盘失败和任务登记失败不被提示为已受理或已入库。
- [ ] 上传任务绑定真实登录用户、独立上传批次、报告日期及至少到市的报告地区；区县可选，层级关系服务端校验。
- [ ] 真实独立工作进程从 PostgreSQL 领取任务，基本领取互斥、租约和副作用保护随本票落地；默认一次解析一个任务，其他任务排队。深入故障注入验收在第 07 票完成。
- [ ] 仅解析 Sheet1；每份最多 30,000 行非空检测数据，不含表头但包含对照行；30,001 行拒绝。沿用现有 8 MiB 字节上限作为默认值，解压与解析内存、时间有边界，兼容性差异须报告。
- [ ] 对照 OR 剔除、富文本规范化、CT 判定、同批次试剂多病原体、有效行重复及整份拒绝规则与规格一致，校验失败反馈必要行号，不返回完整检测明细。
- [ ] 页面与状态接口呈现排队、解析中、待确认和阶段性失败，支持分页任务列表；不展示虚构的百分比。未确认数据不进入大盘。
- [ ] 普通管理员只能读取自己的任务，超管可读取全部；猜测任务标识不能越权。
- [ ] 正常解析成功或业务校验失败后删除原 Excel，不提供原文件下载，也不把原文件纳入数据库或长期备份。遗留文件对账与过期清理在第 07 票补齐。
- [ ] 真实 HTTP、工作进程及浏览器覆盖上传、刷新后找回任务、校验结果和权限；保留既有样表统计基线。
- [ ] 3 人上传最大文件、含排队 5 分钟为设计目标，本票不做并发性能压测，也不声明已达标。
