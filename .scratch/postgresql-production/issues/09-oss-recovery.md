# 09 — OSS 备份与时间点恢复闭环

**What to build:** 维护者可以将 PostgreSQL 基础备份和持续归档日志安全保存到指定 OSS 专用目录，并在隔离目标恢复到指定时间点、核对业务数据。

**Blocked by:** 04 — 确认入库与大盘总览闭环

**Status:** complete

- [x] 使用已确认的武汉 OSS 私有 Bucket（用户最新确认为 floatnoise-wh，见 ADR 0004） 及 Sentry 专用前缀，环境、实例和备份链隔离；不得改桶级设置、访问其他目录或上传原 Excel。
- [x] 采用基础备份及持续 WAL 归档，使用加密传输、完整性校验和限定前缀的最小授权；仅逻辑导出不能算完成时间点恢复。
- [x] 备份身份与秘密安全注入，不进源码、镜像或日志；真实 OSS 访问授权和连通性为外部前置条件，可先实现但未完成实连与恢复不得把整票标为完成。
- [x] 维护最近 30 天恢复窗口及恢复链依赖，必要时保留更早的基础备份和关联日志；测试证明清理不会移除唯一恢复来源。
- [x] 归档失败、延迟、缺口或磁盘不足会产生结构化日志及可查询状态，记录最近成功备份及可恢复时间点；不接外部通知渠道。
- [x] 在专用演练目录和隔离数据库中，使用真实基础备份和日志恢复指定时间点，核对账号登录、提交和作废状态及汇总；禁止覆盖在线库。
- [x] 模拟不可达、凭据失效或缺失日志时恢复明确失败，不将不完整结果当作成功；源数据和备份仍保持受控。
- [x] 恢复后的过期暂存任务与缺失原文件有明确处置规则；接入第 07 票后由最终集成验收验证，不要求本票等待完整清理功能才能开发。
- [x] 记录 RPO 和 RTO 的验证条件、实测结果和未验证范围，恢复时间涵盖环境准备、下载、回放、应用启动及业务核对；不因脚本可运行承诺 15 分钟／1 小时已达标。
- [x] 30 天恢复链规则可以用受控时间测试，新部署不声称已有 30 天真实历史；不进行容量压测或未经批准购买资源。
