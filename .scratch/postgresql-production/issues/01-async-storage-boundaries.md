# 01 — 整理异步存储与事务边界

**What to build:** 在不改变现有用户行为的前提下，使登录、上传、统计和退出可以通过明确的异步存储及事务边界运行，为 PostgreSQL 替换提供可逐步验证的基础。此票是已批准的前置重构例外，不引入新业务功能。

**Blocked by:** 无，可立即开始。

**Status:** in-progress

- [ ] 现有登录、账号管理、Sheet1 解析、确认、历史、作废及地图统计继续正常；真实 HTTP 集成回归、类型检查和生产构建通过。
- [ ] 调用方完整等待异步结果，不向响应序列化未完成的 Promise，也不在异步任务结束前关闭事务或连接。
- [ ] 业务事务有明确的提交、回滚与资源释放边界；异常会回滚，测试验证结果不出现部分提交。
- [ ] 存储访问与 HTTP 生命周期、解析执行解耦，便于后续接入真实数据库和独立工作进程；不为全部模块制造无需求的通用框架。
- [ ] 优先复用现有真实 HTTP 测试及既有统计基线，用外部可观察行为证明重构等价，不以内部调用次数或 SQL 字符串快照作为主要证据。
- [ ] 过渡期旧存储只用于保持逐票集成可用；记录使用者及移除条件，不形成自动降级、双写或最终生产兼容承诺。
- [ ] 不改变线上数据库、不购买资源、不做容量或并发压测。
