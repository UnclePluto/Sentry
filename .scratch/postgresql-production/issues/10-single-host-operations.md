# 10 — 单机部署、资源限制与运行日志

**What to build:** 维护者可以在隔离的单机部署环境运行 Web、API、独立工作进程和 PostgreSQL，并从健康状态和受限日志识别启动、任务及数据库故障。

**Blocked by:** 03 — 上传排队、解析与结果查看

**Status:** in-progress

- [ ] 提供可复现的容器部署方式，运行依赖和数据库版本明确，数据与临时上传目录分别持久化，支持未来外置数据库或工作进程。
- [ ] PostgreSQL 仅在内部网络访问，不开放公网端口；业务 API、管理和展示代理延续现有 HTTPS 域名与路由规则。
- [ ] 按现有 2 核 2 GB 约束记录连接池、解析并发、内存和磁盘预算，限制任务资源竞争；数值作为部署默认值而非压测结论。
- [ ] 数据库、迁移和工作进程有可检查的就绪状态，依赖未就绪不能假报健康；优雅退出、受控重启及实际任务恢复可验证。
- [ ] 通过部署后的浏览器完成登录、身份识别、上传受理与校验结果查看，并验证停用和退出，证明代理前缀与会话布局一致。
- [ ] 日志涵盖请求、任务和错误阶段，带关联标识与耗时；密码、令牌、原文件及检测明细正文不进入日志。
- [ ] 配置日志轮转、保留规则及总量限制，实际预算写入运维说明；磁盘不足可识别，不建立机器人或邮件告警。
- [ ] 备份／恢复日志遵循同样规范，后续第 09 票可以接入；不因等待 OSS 授权阻塞基础部署验证。
- [ ] 本票只完成隔离部署验证和配置，不提前替换线上数据库、不购买新资源、不做容量或并发压测。
