# 11 — 维护模式、生产切换与回退验收

**What to build:** 在受控维护窗口冻结旧系统写入，将经过核对的数据切换至 PostgreSQL，验证真实用户全流程后开放服务，并留下明确的回退与恢复证据。

**Blocked by:** 08 — 现有 SQLite 数据迁移与隔离核对；09 — OSS 备份与时间点恢复闭环；10 — 单机部署、资源限制与运行日志

**Status:** blocked

- [ ] 确认所有阻塞票完成，包括真实 OSS 备份恢复演练及必要访问授权；未验证事项单列，不把模拟测试当作真实备份接通。
- [ ] 依据实时数据盘点和隔离迁移演练制定维护范围、预期时长、失败判据及回退步骤，不凭早期数据估算；保留一致性源快照、旧镜像和配置。
- [ ] 进入维护模式冻结上传、确认、作废、账号修改及其他迁移相关写入，处理在途事务并停止旧工作进程和清理操作；尽量保留只读大盘，不能维持时明确展示维护状态。
- [ ] 基于最终冻结快照迁入 PostgreSQL 并核对账号、标识、数量、约束、归属、状态、总体及各维度统计；有未解释差异时不开放写入。
- [ ] 浏览器验证真实域名下的登录、超管身份和账号管理、普通管理员限制、上传排队、离开后恢复、确认入库、分页历史、整批作废及退出。测试数据使用明确隔离范围，不能污染真实大盘。
- [ ] 验证所有大盘维度在提交与作废后正确更新，原有地图交互与刷新无回归；验证停机恢复、暂存过期、原文件缺失和日志可追踪。
- [ ] 开放写入前演练或验证可回到冻结时的旧镜像与快照；新库开始接受写入后必须先冻结并保全新数据，不可直接切回旧库丢弃新提交。
- [ ] 开放业务写入后验证 PostgreSQL 是唯一运行时业务数据库；旧库和切换快照受控只读保存，不残留双写或自动 SQLite 降级路径。
- [ ] 核对 PostgreSQL 就绪、工作进程、备份归档和日志状态；数据库备份与恢复目标的实际验证证据归档，无外部告警的限制明确保留。
- [ ] 运行真实 HTTP 集成、浏览器回归、类型检查、生产构建及上线冒烟，记录每项结果；不进行容量或并发压测。
- [ ] 交付运行与恢复说明，明确已验证功能、未验证性能和未来扩容条件；不得承诺现有 2 核 2 GB 已满足千万条、P95、最大上传负载或无条件 RPO／RTO。
