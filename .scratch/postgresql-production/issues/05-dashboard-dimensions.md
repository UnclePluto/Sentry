# 05 — 完整大盘统计与汇总重建

**What to build:** 大盘的日期、病原体、排行、趋势、时空分布和地区下钻全部读取 PostgreSQL 汇总，维护者能够核对并重建汇总，用户不会看到混合版本统计。

**Blocked by:** 04 — 确认入库与大盘总览闭环

**Status:** in-progress

- [ ] 总体及病原体筛选使用正确分子分母，不平均阳性率、不把未出现的病原体结果推定为阴性；维持既有各模块时间展示方式。
- [ ] 全国和省级统计纳入市级及区县级提交，市内区县视图排除仅到市的提交；直辖市同样正确，地图与相关图表地区集合一致。
- [ ] 演示与真实数据隔离；日期依据报告日期，公共大盘不受管理员个人历史权限过滤。
- [ ] 排行、趋势、时空分布及地图的常规请求只读取持久化汇总并由 PostgreSQL 聚合，返回规模受控；不新建全量明细搬运逻辑。
- [ ] 提供从长期明细重建和核对汇总的维护能力，重建时采用一致性切换，不能让大盘同时读取半套新旧汇总。
- [ ] 小数据基准验证各日期、病原体和地区维度与既有业务口径一致；重建前后相等，故意破坏测试汇总后能识别差异并恢复。
- [ ] 维护现有 2D／3D、拖拽、锁定及下钻效果；自动刷新不重新触发整张地图渐隐，浏览器和现有地图回归通过。
- [ ] 1,000 万条、20 个大盘、统计接口 P95 ≤ 2 秒为设计目标；本票不造千万条数据、不做容量或并发压测。
