# 08 — 现有 SQLite 数据迁移与隔离核对

**What to build:** 维护者能将一致性的 SQLite 快照迁入隔离 PostgreSQL，并以原账号登录、核对历史和大盘；迁移失败可定位且安全重跑，正式运行不再依赖 SQLite。

**Blocked by:** 05 — 完整大盘统计与汇总重建；07 — 任务故障恢复、取消与过期清理

**Status:** complete

- [x] 基于当前数据只读盘点账号、批次、试剂、检测结果、状态及业务统计，不沿用早期只有演示数据的假设。
- [x] 制作并校验一致性 SQLite 快照，正确处理活动数据库及 WAL，不把直接复制正在变化的单文件当作合格备份；保留源库和校验记录。
- [x] 完整映射账号、密码哈希、角色和启用状态、提交标识与归属、日期、地区、结果、原始汇总及作废审计；保留标识或提供完整映射证据。
- [x] 旧待确认预览有明确新状态和有效期，不能静默丢弃或自动发布；过期处理遵守已确认规则。
- [x] 从明细重建 PostgreSQL 汇总，核对总体、日期、病原体、各级地区及直辖市范围，包含市级提交、演示和真实数据的隔离。
- [x] 导入中断可恢复或安全重跑，不重复计数；非预期目标数据不被自动清空，约束或统计差异会导致核对失败。
- [x] 隔离迁移后通过真实浏览器使用既有账号验证身份、账号管理、任务／历史和大盘数据；角色和停用状态不被绕过。
- [x] 移除正常运行中的 SQLite 适配、自动降级和旧连接路径；仅保留离线迁移读取与受控旧版本回退来源。生产应用仍运行旧镜像，直到最终切换票。
- [x] 输出数量、关键字段及多维统计核对报告、已知差异和演练耗时，不在报告中泄露凭据或逐条检测数据。
- [x] 不操作生产切换，不做千万条造数或性能压测；最终维护模式及开放写入由第 11 票负责。
