# 02 — PostgreSQL 登录与账号管理闭环

**What to build:** 在隔离 PostgreSQL 环境中，管理员可以通过真实后台页面登录、管理账号、修改密码并退出；账号、权限和会话跨应用重启保持正确。

**Blocked by:** 01 — 整理异步存储与事务边界

**Status:** in-progress

- [ ] 使用真实 PostgreSQL、参数化查询及有上限的连接池，配置连接与语句超时；就绪检查在数据库或所需迁移不可用时明确失败。
- [ ] 数据库结构版本可检查、迁移可安全重复执行；多进程启动不会重复执行冲突迁移或生成多个初始超管。
- [ ] 初始超管凭据只在确有需要时生成并安全保存；已存在账号不被重置。密码哈希格式兼容既有账号，导入已有账号的验收由迁移票完成。
- [ ] 登录、当前会话、退出、改密及超管创建、停用、启用、重置和删除管理员行为正确；停用和改密后的旧会话不能继续越权。
- [ ] 会话与登录频率限制使用共享持久化状态，不依赖某个 API 进程的本地内存；同一事务固定使用同一连接。
- [ ] HTTPS Cookie、来源校验和接口权限不退化；运行时、迁移及数据库管理身份的权限边界明确，秘密通过环境安全注入且不写入日志。
- [ ] 真实浏览器验证登录表单调用正确接口、超管身份及账号管理入口、普通管理员限制和退出，不以直接调用登录 API 代替页面验收。
- [ ] 延续大盘与后台的路由隔离及既有入口；本票可在专用测试环境演示，不要求将不完整的 PostgreSQL 功能发布线上。
