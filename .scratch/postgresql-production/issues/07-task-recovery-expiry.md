# 07 — 任务故障恢复、取消与过期清理

**What to build:** 服务重启、网络中断或任务过期后，管理员能看到可解释且可恢复的任务结果，取消与清理不会破坏已经提交的数据。

**Blocked by:** 06 — 提交历史与整批作废闭环

**Status:** complete

- [x] 通过受控停止 API 或工作进程验证已接收任务仍可查询，过期租约可接管，旧执行者恢复后不能覆盖新结果或重复发布。
- [x] 基础设施错误有界重试并记录次数与阶段；业务校验错误要求修正文件，不无限重试。权限和归属在用户重试操作时重新验证。
- [x] 允许状态下取消任务会停止后续业务副作用并最终删除原文件；确认中、已提交及已作废的取消请求不能绕过业务状态规则。
- [x] 覆盖上传中断、文件已落盘但登记失败、任务文件丢失、删除失败及重启对账；恢复后缺少原文件的任务明确失败，提示重新上传。
- [x] 解析成功、校验失败或取消后的原文件删除可重试；异常原文件自接收起最长 24 小时，到期清理并将相关任务明确终止，不删除仍需保留的正式数据。
- [x] 待确认结构化数据自校验结果生成起保留 7 天，过期后清理暂存明细，保留任务摘要及过期状态。已提交明细长期保留。
- [x] 到期清理与确认原子竞争：已被合法提交接管的数据不被误清理，逾期才发起的确认明确拒绝；确认、作废及取消相互一致。
- [x] 数据库恢复后重新计算暂存有效期，不让过期任务复活；终止状态可在任务列表中观察。
- [x] 测试使用隔离 PostgreSQL、实际工作进程、小数据故障注入及可控时间，不等待数天，不进行并发性能压测；补充页面失败、取消、重试和过期反馈。
