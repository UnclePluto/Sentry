# 首版使用 PostgreSQL 持久化任务，不引入 Redis

在累计 1,000 万条有效明细、最多 20 个大盘同时在线、1～3 位管理员同时上传的目标下，首版采用 PostgreSQL 保存业务数据、统计汇总、会话及持久化任务状态，由独立后台工作进程处理导入。用户确认首版不引入 Redis，以减少运维组件；统计性能通过汇总查询解决，实际容量仍需压测验证。

任务领取、防止重复处理、超时重试和重启恢复必须在 PostgreSQL 与工作进程之间实现，不能以进程内队列替代持久化任务。未来若共享缓存或任务调度出现经验证的瓶颈，再评估 Redis。该决策不代表完整生产架构已确认，讨论结束前不恢复实施。
