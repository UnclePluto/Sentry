# 0004 — 将数据库备份目标切换为武汉 OSS

日期：2026-09-16。状态：用户确认。

用户将原上海备份目标改为武汉 endpoint `oss-cn-wuhan-lr.aliyuncs.com`，并明确 Bucket 为 `floatnoise-wh`。当前 ECS 位于 `cn-wuhan-lr`。

部署显式提供 `SENTRY_OSS_BUCKET` 与 `SENTRY_OSS_ENDPOINT`，签名地域从经过校验的 endpoint 推导；缺少配置直接失败。保留命名空间 `sentry/postgresql/<环境>/<实例>/`、30 天恢复窗口及其依赖链，不修改桶级 ACL、版本控制或生命周期。

`SentryBackupRole` 已绑定 ECS，`SentryPostgresBackupPrefix` 的默认策略仅允许武汉桶专用前缀的对象操作与限定前缀列举。主账户凭据仅用于本轮授权的控制面配置，未保存到项目或服务器；数据库和备份进程始终使用 ECS 角色临时凭据。

实连发现精简数据库镜像缺少 CA 证书，正式镜像显式安装 `ca-certificates`；禁止以关闭证书校验代替修复。

真实 OSS 演练使用随机环境前缀和临时容器／数据卷，不改在线库。源账号字段在备份前保存在进程内存，恢复后在启动 API 前核对原账号及密码哈希，再验证登录。临时资源清理失败须输出残留资源并返回失败。OSS 演练前缀保留为验收证据，后续仅能针对记录的完整演练前缀清理，不执行桶级清理。

本决定更新备份目标，不重写已经确认的父规格历史。恢复与切换证据另记于实施报告；性能、容量和灾难恢复目标仍按实测范围报告。
